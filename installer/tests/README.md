# 安装器集成验证

`integration.py` 使用真实的打包、安装、入口与结构检查代码，加上很小的假 Wine 运行库。它只修改新建的临时测试目录；不会运行真实 Wine、游戏、官方启动器，也不会修改桌面和 `/Applications`。

在 Apple Silicon、macOS 26+ 且已安装 Rosetta 2 的开发机上执行：

```sh
python3 installer/tests/integration.py --output /tmp/endfield-installer-check
```

可加 `--test-exfat` 创建并挂载一个临时 64 MiB ExFAT 磁盘映像，验证安装器在修改目标目录前明确拒绝该文件系统，之后正常卸载映像。不会格式化或操作真实外置盘。

如果用户正在运行真实 Wine，可以加 `--isolate-process-check`。此选项只修改本轮合成安装器资源的进程列表来源，列表仅包含测试自己的假 `wineserver`，仍用原有解析规则测试忙碌状态；不修改产品源码、不终止真实进程。结果报告会明确标记进程列表是模拟的。不能据此声称已在真实 Wine 活跃时执行了真实安装。

覆盖全新安装、v0.2/v0.3 升级、旧启动器状态优先迁移、DX11 状态回退、同版重装、初始化失败与提交后验证失败的回滚、损坏包、非管理目录、外部目录链接、并发锁、运行中拒绝、中文及特殊字符路径、升级前后整体移动目录、旧入口统一打开官方启动器及启动失败后等待进程结束。

还检查可选 Mono/HTML 组件的禁用项仅作用于 `wineboot.exe` 初始化命令，后续注册表导入和所有游戏入口都恢复原有渲染 DLL 配置；显式使用 `wineboot.exe` / `reg.exe`，不会依赖裸文件名搜索。

故障注入还核对主安装日志：预检查保留具体原因；Wine 初始化保留退出码42和原始错误；内部校验、官方 EXE 解压错误从分日志传回主日志；最终验证失败不会夹入上次安装的 Wine 错误。

自动清理验证使用一次性夹具：成功升级后清除旧独立用户环境、运行库及已识别备份，保留当前 `State`、游戏、官方启动器及已识别清理子树之外的个人文件；两种安装失败均保留旧环境。清理脚本失败、已提交后的备份暂存失败、工作目录删除失败均不会撤销或误报已完成安装，并保留可检查的现场。还覆盖重复清理、旧备份格式、不跟随游戏/外部目录链接、大小写不同的 `Endfield.exe` / `Endfield_Data` 实体数据保留，以及无法确认归属的运行库与清理子树之外的自定义文件保留。旧环境因实体游戏被保留时，归属标记继续保留；把夹具中的游戏移到 `Game` 后，再次清理可完成剩余环境清理。已识别旧根目录日志会删除，当前诊断、会话日志、链接和自定义日志保留。

默认还用隔离的 `diskutil` 元数据替身验证 APFS/HFS 可用、ExFAT/FAT/NTFS 被拒绝的分支。此项明确为模拟文件系统测试，不能作为真实外置盘测试的结论。可选磁盘映像测试若被本机权限限制拒绝，会如实失败并保留原因，不会尝试提权或操作真实磁盘。

每条命令的输出与汇总 `results.json` 保留在指定目录。假运行库验证安装事务与路径行为，不能替代真实游戏兼容性验证。
